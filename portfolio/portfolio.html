모델은 도구가 돌려준 결과만 근거로 말한다. 출력은 JSON 스키마로 강제하고, rationale의 항목마다 evidence_ids를 요구한다. 도구가 돌려준 적 없는 근거 id가 섞이면 검증기가 반려하고 한 번 더 기회를 준 뒤 그래도 실패하면 사람에게 넘긴다.

운영 흐름

매일 새벽 스캔이 끝나면 아침에 「오늘 고칠 열 건」 보고서가 올라온다. 왜 이 열 건인지의 근거, 예상 소요, 담당자가 함께 적혀 있고 개발자는 PR 초안을 검토해 적용한다. 재스캔이 0건을 확인하면 티켓이 닫힌다.

본선 1박 2일 구현 범위: 제공 데이터 어댑터 → 우선순위 엔진 → 상위 열 건 조치안 → 한 건 이상 실제 패치와 재스캔 시연. 이 포트폴리오의 코드가 그 출발점이다.

에이전트는 조치안과 PR 초안까지. 병합과 배포는 사람이 승인한다.

  • 상위 10건 소멸 pygoat 9건, netbox 8건, nodegoat 4건. 소멸하지 않은 건은 전부 메이저 업그레이드가 필요한 취약점이었다. Django 3.2는 지원이 끝난 브랜치라 2025년 이후 CVE는 4.2·5.x에서만 고쳐졌고, Pillow 12의 2026년 10월 신규 어드바이저리 41건은 13.0.0이 수정 버전이다.
  • 업그레이드가 새 취약점을 들여오기도 한다. NetBox의 Pillow를 10.0.1로 올리자 10.x 범위에서 시작하는 어드바이저리 6건이 새로 잡혔다. 예상 10건 소멸은 맞았지만 잔존 수는 예상보다 많았고, 이 차이가 다음 조치 라운드의 입력이 된다.
  • NodeGoat는 비파괴적 변경만 적용했다. 운영 의존성 취약 패키지 52개 중 22개가 semver 호환 범위 안에서 해결됐고, 남은 30개는 메이저 변경이거나 패치가 없다. marked 0.3.5는 4.0.10으로, 유지보수가 끝난 swig는 대체 패키지 검토가 완화책이다.

  • 함수 수준 도달성. 어드바이저리가 지목한 취약 API의 실제 호출 여부를 code_search로 확인해 R 값을 정밀화한다.
  • OpenAI 모델 기반 조치안 생성 실행본. 이번 포트폴리오의 조치안은 같은 도구와 스키마를 쓰는 규칙 기반 초안이며, 본선 환경에서 모델 실행본으로 교체한다.
  • 평가셋 지표: 상위 열 건 정확도, 재스캔 통과율, 근거 없는 문장 비율을 회귀 테스트로 추적.

정직하게 적는 한계

  • 서비스 인벤토리의 노출면·중요도·담당은 데모용 가정값이다.
  • 도달성은 패키지 수준 import 확인까지만 구현했다.
  • Python은 고정 핀만 감사했고 전이 의존성은 npm 쪽에서만 다뤘다.
